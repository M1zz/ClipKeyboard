# 4.4.5 릴리즈 노트

앱 스토어 "이번 버전의 새로운 기능"에 그대로 붙여 넣을 수 있는 문안입니다.
(앱 안 변경 이력은 `ChangelogView.swift` 의 `4.4.5` 항목, 저장소 기록은 `HISTORY.md`)

아래 두 문안은 **특수기호를 쓰지 않은 평문**입니다. App Store Connect 의 입력칸은
마크다운을 해석하지 않아서, 별표나 가운뎃점을 넣으면 그 글자가 그대로 보입니다.
그대로 복사해 붙이면 됩니다.

## 한국어 (App Store)

```
앱을 열면 키보드가 올라온 모습이 그대로 보입니다. 처음 쓰시는 분은 단축어 하나를 직접 만들고, 눌러서 써 보는 데까지 안내를 따라가면 됩니다.
```

## 심사·배포 메모 (내부)

문안은 당시 그대로다. 특수기호(별표, 가운뎃점, 불릿)만 걷어내고
템플릿 모양을 맞췄다.

- **버전**: `Version.xcconfig` 의 `MARKETING_VERSION = 4.4.5`. 빌드 번호는 업로드 전 올릴 것.
- **새 권한 없음**, 추가된 권한·엔타이틀먼트 없음.
- 4.4.4 의 심사 메모(붙여넣기 프롬프트 시점, 키보드 감지, 스킨 비노출, 자산 감소, 튜토리얼 상태 키,
  **인도네시아어 정리 미완**, macOS 앱 호환성)는 **전부 그대로 유효하다**
  `docs/release-notes/4.4.4.md` 의 같은 절을 볼 것. 4.4.4 가 안 나갔으므로 이번에 함께 나간다.

### 🚨 배포 순서, CloudKit 스키마가 앱보다 먼저

익명 사용 통계 이벤트에 **발생 시각(`occurredAt`)** 필드가 새로 들어갔다.
Production 스키마는 잠겨 있어, 레코드 타입에 없는 필드를 담아 저장하면 **그 저장이 실패한다.**
스키마 배포 전에 앱이 먼저 나가면 `app_open` 을 포함한 **이벤트 전송이 통째로 실패한다**(스냅샷은 무사).

1. 새 빌드를 **Development 환경**에서 한 번 실행하고 주요 행동을 한 번 한다
   → `UsageEvent` 에 `occurredAt` 필드가 자동 생성된다.
2. CloudKit Dashboard 에서 필드가 생겼는지 확인한다.
3. **Schema → Deploy Schema Changes to Production.**
4. 그 다음에 심사에 올린다.

자세한 배경은 `docs/engineering/USAGE_STATS_HUB.md`.

### 🚨 같은 자리에서 백업·동기화 스키마도 함께 본다 (4.4.3 사용자 제보)

4.4.3 사용자에게서 **백업이 매번 실패하고, 맥과의 동기화에서 삭제·수정만 전달되지 않는다**는
제보가 왔다. 증상이 `occurredAt` 과 **같은 뿌리**(Production 스키마에 없는 필드를 쓰면 그 저장만
실패)일 가능성이 가장 크다. 위 3번 배포 전에 아래를 함께 확인할 것.

| 레코드 타입 | 있어야 하는 필드 | 없으면 생기는 일 |
|---|---|---|
| `Memo` | `payload`, `lastEdited`, **`deletedAt`**, `images`, `imageNames` | `deletedAt` 이 없으면 **삭제만** 전달되지 않는다. 추가·수정은 멀쩡해서 원인이 안 보인다 |
| `Backup` | `memosAsset`, `smartClipboardAsset`, `combosAsset`, `memoCount`, `imageAssets`, `imageNames`, **`categoriesAsset`** | `categoriesAsset` 은 4.4.4 에서 새로 추가됐다. 미배포면 **모든 사용자의 백업이 실패**한다 |
| `CategorySettings`, `BackupSnapshot`, `BackupIndex` | 타입 자체의 존재 | 스냅샷·카테고리 동기화가 조용히 실패 |

⚠️ **Development 환경에서는 필드가 자동 생성되므로 개발 중에는 절대 재현되지 않는다.**
그 필드를 쓰는 동작(메모 삭제, 이미지 있는 메모 백업)을 Development 에서 한 번씩 해 본 뒤
Production 으로 배포해야 스키마가 생긴다. 특히 **삭제는 테스트에서 빠뜨리기 쉽다.**

관련해 다음 버전에 넣을 것(이번 4.4.5 범위 아님):
- 오류 문구에 CKError 코드를 노출한다. 지금은 스키마·충돌·디스크 문제가 **전부 같은 한 문장**으로
  보여서 제보만으로는 원인을 못 가른다(`CloudKitBackupService.swift:55-83`).
- 설정에 동기화 상태(`MemoSyncStatus` 의 마지막 오류·수신·전송)를 보여주는 행. 기록은 이미
  다 하고 있는데 **읽는 화면이 iOS 에도 맥에도 없다.**
- `serverRecordChanged`(충돌)를 재시도 대상에 넣기. 아이폰·맥이 `TokenMemoBackup` 한 레코드를
  같이 덮어쓰는 구조라 충돌이 나는데 즉시 실패로 끝난다.
- `createAsset` 의 임시 파일명에 UUID 붙이기 + `isBackingUp` 을 실제 직렬화로. 자동 백업(5분 타이머,
  데이터 변경 5초 뒤)과 수동 백업이 겹치면 같은 임시 파일을 밟는다.

### 그 밖에 이번 버전에서 바뀐 내부 동작

- **LeeoKit 2.6.0 → 2.9.0** (`release/2.x` 유지보수 라인). 3.x 는 `LeeoAppSpec` 에
  `legal`·`monetization` 을 강제하는 breaking 변경이라 **일부러 올리지 않았다.**
- **키보드만 쓰는 사용자도 집계된다**, 익스텐션이 App Group 에 날짜별 활동 원장을 쌓고,
  앱이 열리거나 백그라운드 새로고침이 돌 때 그날 날짜 그대로 소급 전송한다.
  전송이 확정된 날만 원장에서 지우므로 iCloud 미로그인 기간의 기록도 유실되지 않는다.
- **`app_open` 의 뜻이 정확해졌다**, 예전에는 백그라운드 새로고침으로 프로세스만 깨어나도
  찍혔다. 이제 화면이 실제로 뜬 경우에만 남는다(활성 사용자 수가 조금 낮게, 대신 정확하게 나온다).
- **백그라운드 task 가 전송을 기다린다**, 예전에는 `setTaskCompleted` 를 즉시 불러
  CloudKit 쓰기가 시작하자마자 잘렸다.
- **엠대시(U+2014)를 저장소 전체에서 걷어냈다**(3,236곳). UI 문자열·String Catalog 도 포함이라
  **번역 키가 함께 바뀌었다.** 코드 리터럴과 카탈로그 키에 같은 변환을 적용해 1,409개 키가
  전부 붙어 있는 것을 확인했다(누락 0). 앞으로의 규칙은 `CLAUDE.md` "문장부호" 절.
  ⚠️ 그 과정에서 **"없음" 표시로 쓰이던 대시 글리프**(`PaywallView` 비교표, 콤보 단계 빈 값,
  키보드 값 미리보기)가 빈 문자열이 되는 회귀가 있었다. 하이픈으로 되살렸으니
  **심사 전 페이월 비교표의 무료 열이 비어 보이지 않는지 눈으로 확인할 것.**

### ⚠️ 잠금화면에서의 의미가 달라졌다 (제어센터·위젯 복사)

예전에는 위젯을 눌러도 앱이 뜨느라 **잠금 해제를 거쳐야** 값이 복사됐다.
이제는 잠긴 채로도 복사된다. 요청받은 편의지만, 남이 잠긴 폰을 집어 들면
즐겨찾기 값을 클립보드에 담을 수는 있다는 뜻이기도 하다.

- 대상은 **사용자가 직접 즐겨찾기한 비보안 단축어**로만 한정된다(`loadFavoriteMemos`).
- 보안 단축어는 이 경로에 아예 오르지 않는다.
- 잠금화면에서 이 동작을 원치 않는 사람을 위한 스위치는 **아직 없다.**
  지적이 들어오면 App Group 플래그 하나로 잠금 상태 복사를 막는 것이 가장 빠른 해법이다.
