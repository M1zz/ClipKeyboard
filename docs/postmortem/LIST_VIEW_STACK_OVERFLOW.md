# 목록 화면을 그리다 스택이 넘쳐 죽는다

- **증상**: 기기에서 Debug 로 실행하면 목록 화면이 뜨는 순간 죽는다.
  Xcode 는 `ClipKeyboardList.screenL3` 의 `screenBody2` 줄에 `Thread 1: EXC_BAD_ACCESS (code=2, address=0x16b80bfc0)` 를 띄운다.
  시뮬레이터에서는 죽지 않는다.
- **읽는 법**: `code=2` 이고 주소가 `0x16b...` 처럼 스택 근처면 스택의 보호 페이지를 밟은 것이다. 그 줄의 코드가 틀린 것이 아니다.

## 원인

`ClipKeyboardList` 는 `@State` 가 많아 값 하나가 4KB 가 넘고, `screenBody` 부터 `screenL8` 까지 수식어를 붙일수록 커져 맨 바깥이 13KB 였다.
최적화가 없는 Debug 빌드는 수식어 하나마다 그 값을 스택에 한 번 더 복사한다. 여덟 단계가 서로를 부르므로 그 복사본이 전부 겹쳐 쌓인다.

| | 체인이 쓰는 스택 (`body` 에서 `screenBody` 진입까지) |
| --- | --- |
| 고치기 전 | 약 850KB |
| 고친 뒤 | 약 190KB |

기기의 메인 스레드 스택은 1MB, 시뮬레이터는 8MB 다. 그래서 기기에서만 죽고, 화면에 무엇을 더할 때마다 조금씩 가까워지다가 넘었다.

## 고친 것

단계마다 안쪽 화면을 `AnyView` 로 감싸서 받는다. 값이 힙으로 가고 참조만 넘어가므로 단계마다 크기가 다시 작아진다
(맨 바깥 13KB 에서 1KB 아래로).

## 다시 재려면

`pthread_get_stackaddr_np(pthread_self())` 에서 지역 변수의 주소를 빼면 그 자리까지 쓴 스택이다.
`body` 와 `screenBody` 첫 줄에서 찍어 차이를 본다. 300KB 를 넘기 시작하면 단계를 더 나누거나 `@State` 묶음을 다른 뷰로 뗀다.
