# 보안 메모, 암호화 · 권한 · 데이터 경계

> 완성도 체크리스트 🔐의 "전송·저장 암호화"와 "최소 권한 요청"에 대한 근거 기록.
> 코드 실사 기준일: **2026-07-31**. 판단이 바뀌면 이 문서도 같이 고친다.

## 1. 요청하는 권한: 딱 하나

| 권한 | 쓰는 곳 | 안 주면 |
|---|---|---|
| **카메라** (`NSCameraUsageDescription`) | 카드·문서 촬영 후 OCR(Vision) | 촬영 기능만 막히고 앱은 정상 동작 |

**그 외에는 아무 권한도 요청하지 않는다.**

- **사진 라이브러리**: `PHPicker` 를 쓴다 → 시스템이 고른 사진만 넘겨주므로 **권한 요청 자체가 없다**.
  (`NSPhotoLibraryUsageDescription` 이 없는 게 정상이다. 있으면 오히려 과잉 요청이다.)
- **위치·연락처·마이크·캘린더·알림**: 요청하지 않음.
- **추적(ATT)**: 요청하지 않음. `NSPrivacyTracking = false`.

### 1-1. 키보드 "전체 접근 허용"에 대하여

`ClipKeyboardExtension/Info.plist` 의 `RequestsOpenAccess = true`.

사용자가 가장 불안해하는 권한이므로 **왜 필요한지가 분명해야 한다**:

- 이유는 **하나뿐**, App Group 컨테이너(`group.com.Ysoup.TokenMemo`)에서 저장된 단축어를 읽기 위해서다.
  이 권한이 없으면 키보드는 자기 샌드박스만 볼 수 있어 앱에서 만든 단축어를 못 읽는다.
- 키보드는 **입력한 텍스트를 저장하지도, 전송하지도 않는다.**
- 키보드 익스텐션 엔타이틀먼트에는 **App Group만** 있다. iCloud/CloudKit 컨테이너가 없어서
  네트워크로 내보낼 경로 자체가 없다(최소 권한의 구조적 보장).

| 타깃 | 엔타이틀먼트 |
|---|---|
| 앱 | App Group + iCloud(TokenMemo, FeedbackHub) + Keychain |
| **키보드** | **App Group 만** |
| **위젯** | **App Group 만** |
| 공유 확장 | App Group |

## 2. 저장 암호화

| 데이터 | 어디에 | 보호 |
|---|---|---|
| 일반 단축어·클립보드 | App Group 컨테이너 파일 | iOS 파일 보호 **기본값**(`CompleteUntilFirstUserAuthentication`) + 기기 전체 암호화 |
| **보안 단축어** | 같은 파일, **값만 암호문** | **AES-GCM** (`SecureMemoCrypto`) |
| 암호화 키 | **iCloud Keychain**(동기화) | `kSecAttrAccessibleAfterFirstUnlock` |
| iCloud 백업 | 사용자 개인 CloudKit DB | Apple이 전송·저장 구간 암호화. 개발자 접근 불가 |
| 통계·피드백·크래시 | 공개 CloudKit DB | HTTPS 전송. **애초에 민감 정보를 안 보낸다**(집계 수치·이벤트 이름뿐) |

### 2-1. 파일 보호 등급을 올리지 않은 이유 (의도적)

`.completeFileProtection`(잠금 시 접근 불가)으로 올리면 보안은 세지지만
**키보드 익스텐션이 깨진다.** 키보드는 기기가 잠긴 직후·잠금화면 위에서도 뜰 수 있는데,
그때 App Group 파일을 못 읽으면 단축어 목록이 빈 채로 나온다.

`AfterFirstUnlock` 계열(현재 기본값)이 이 앱의 사용 형태에 맞는 선택이다.
정말 민감한 값은 **보안 단축어(AES-GCM + 생체인증)** 로 따로 보호한다. 등급을 통째로
올리는 대신 민감한 것만 강하게 보호하는 쪽을 택했다.

### 2-2. 보안 단축어의 실제 보호 범위

- 값은 AES-GCM 암호문으로 저장 → 파일을 통째로 빼내도 평문이 안 보인다.
- 열람 시 **생체인증(LocalAuthentication)** 또는 PIN.
- 키는 iCloud Keychain에 있어 사용자의 다른 기기에서도 열리지만, **개발자는 접근할 수 없다**.
- ⚠️ 한계: 기기가 이미 잠금 해제됐고 앱이 열려 있는 상태라면, 보안 단축어를 열람하는 순간
  평문이 메모리에 존재한다. 이건 어떤 앱도 피할 수 없는 지점이다.

## 3. 데이터가 나가는 경로 (전부 나열)

이 목록에 없는 경로로는 데이터가 기기를 떠나지 않는다.

| 경로 | 무엇이 | 언제 | 끌 수 있나 |
|---|---|---|---|
| iCloud 백업 | 단축어 전체(사용자 개인 DB) | 사용자가 켰을 때만 | ✅ 설정에서 |
| 기기 간 동기화 | 단축어(사용자 개인 DB) | Pro + 사용자가 켰을 때만 | ✅ 설정 / 원격 킬스위치 |
| 사용 통계 | 집계 수치·이벤트 **이름** | 항상 | ⚠️ 앱 내 토글 없음 · 원격 킬스위치만 |
| 크래시 진단 | 콜스택·앱버전·OS | 항상 | ⚠️ 위와 동일 |
| 피드백 | 사용자가 쓴 내용(+선택 입력한 이름·이메일) | 사용자가 보낼 때만 | ✅ 안 보내면 됨 |

> ⚠️ 사용 통계에 앱 내 옵트아웃이 없는 것은 앱 소유자의 의식적 선택이다.
> 심사·GDPR 지적 가능성과 대응 방법: `docs/product/APP_PRIVACY_ANSWERS.md` 4절.

## 4. 하지 않는 것

- 서드파티 SDK **0개**, 분석·광고·크래시 SDK 전부 없음. 우리가 안 보는 데이터를 남이 볼 수도 없다.
- IDFA/IDFV·광고 식별자 미사용.
- 사용자 계정 없음 → 유출될 비밀번호·세션이 없다.
- 자체 서버 없음 → 우리가 운영하는 침해 대상 인프라가 없다.
