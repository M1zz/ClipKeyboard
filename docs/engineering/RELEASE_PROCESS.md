# 릴리즈 프로세스, 베타 · 회귀 · 리뷰 · 롤백

> 완성도 체크리스트 🧪QA의 "베타 테스트 / 회귀 테스트 루틴 / 코드 리뷰 프로세스"와
> 🛟장애 대응의 "롤백 전략"을 한 문서로 정리한다.
> 1인 개발이라는 전제를 숨기지 않고, **혼자서도 지킬 수 있는 최소 규칙**만 남긴다.

## 0. 릴리즈 한 장 요약

```
코드 변경 → CI 그린 → 회귀 체크리스트 → TestFlight(3일) → 단계적 출시 → 지표 확인
                ↑                                                    ↓
            (실패 시 머지 금지)                              이상 시 롤백(4절)
```

---

## 1. 코드 리뷰 프로세스 (1인 개발용)

리뷰어가 없다고 리뷰를 건너뛰면, 리뷰가 잡아야 할 것을 **사용자가 잡게 된다.**
사람 대신 다음 셋을 머지 조건으로 삼는다.

| 게이트 | 도구 | 통과 기준 |
|---|---|---|
| 자동 검증 | `.github/workflows/ci.yml` | 빌드·테스트·다국어 검사 전부 그린 |
| 정적 분석 | `swiftlint` | **신규** 위반 0 (기존 13건은 별도 부채) |
| 논리 검토 | `/code-review` | 지적 사항 해소 또는 "안 고치는 이유" 기록 |

- `main` 직접 푸시 금지. 작업은 `dev` 또는 기능 브랜치에서.
- 커밋 메시지에 **왜**를 남긴다. 1인 개발에서 3개월 뒤의 나는 남이다.
- 리뷰 없이 넘어가도 되는 예외: 문서·주석만 수정, 릴리즈 노트, 버전 번호.

## 2. 회귀 테스트 체크리스트 (릴리즈 전 필수)

자동 테스트 427개가 커버하지 못하는 **손으로만 확인되는 것들**이다.
`docs/engineering/TESTING_GUIDE.md` 의 상세 절차를 요약해 통과 기준만 남긴다.

### 2-1. 앱 ↔ 키보드 데이터 공유 (App Group)
- [ ] 앱에서 단축어 추가 → 키보드에서 즉시 보임
- [ ] 키보드에서 사용 → 앱의 사용 횟수 증가
- [ ] 여러 값 단축어: 키보드 2/3 분할, → 로 값 전환

### 2-2. 데이터 보존 (가장 중요)
- [ ] 구버전 데이터로 업데이트 설치 → 단축어·카테고리 유실 없음
- [ ] iCloud 백업 → 앱 삭제 → 재설치 → 복원 성공
- [ ] 기기 간 동기화 켠 상태에서 양쪽 수정 → 충돌 해결(최신 우선) 확인
- [ ] **모든 데이터 삭제** 실행 → 실제로 다 지워지고 Pro 권한은 유지

### 2-3. 결제
- [ ] 페이월 → 구매 → Pro 기능 즉시 해제
- [ ] 구매 복원 (다른 기기 / 재설치)
- [ ] 결제 취소 → 앱이 정상 상태로 복귀

### 2-4. 다국어·접근성
- [ ] iOS 언어를 영어/인도네시아어로 변경 → 한국어 노출 없음, 레이아웃 안 깨짐
- [ ] VoiceOver로 메인 화면 전체 탐색 가능
- [ ] 다이내믹 타입 최대 크기에서 글자 잘림 없음

### 2-5. 기기 폭
- [ ] iPhone (노치/다이내믹 아일랜드), 상하단 콘텐츠 가림 없음
- [ ] iPad, 앱·키보드·공유확장·위젯 전부 동작
- [ ] Mac (Catalyst), 메뉴바·전역 단축키

> ⚠️ 하나라도 실패하면 릴리즈를 멈춘다. "다음 버전에 고치지"가 데이터 유실을 만든다.

## 3. TestFlight 베타 루틴

| 항목 | 기준 |
|---|---|
| 대상 | 외부 테스터 **3명 이상** (없으면 최소 본인 기기 2대 + 다른 iOS 버전) |
| 기간 | **최소 3일**, 크래시는 보통 첫 이틀에 나온다 |
| 필수 확인 | 2절 회귀 체크리스트 전체 + 신규 기능 |
| 승격 조건 | 기간 내 크래시 0건, 치명적 피드백 0건 |

- 베타 빌드에서도 **사용 통계·크래시 진단이 켜져 있다** → `설정 > 지원 > 사용 통계`(마스터 모드)에서 확인.
- 데이터 스키마가 바뀌는 릴리즈는 기간을 **7일**로 늘린다. 마이그레이션 사고는 되돌릴 수 없다.

## 4. 롤백 전략

App Store는 "이전 버전으로 되돌리기" 버튼이 없다. **미리 정해둔 순서대로** 움직여야 한다.

### 4-1. 단계적 출시(Phased Release)를 항상 켠다
App Store Connect → 버전 → **Phased Release for Automatic Updates 활성화**.
7일에 걸쳐 1%→2%→5%→10%→20%→50%→100% 로 퍼지므로, 초기에 멈추면 피해가 작다.

### 4-2. 사고 등급별 대응

| 등급 | 예시 | 조치 | 소요 |
|---|---|---|---|
| **A. 데이터 유실·크래시 급증** | 저장 실패, 실행 즉시 크래시 | ① 단계적 출시 **일시 중지** ② 원격 킬스위치로 원인 기능 차단 ③ 수정본 긴급 심사 요청 | 킬스위치 즉시 / 심사 1~2일 |
| **B. 특정 기능 오동작** | 동기화 꼬임, 페이월 안 뜸 | 원격 킬스위치로 해당 기능만 끔 → 다음 정기 릴리즈에서 수정 | 즉시 |
| **C. 사소한 UI 문제** | 문구 오타, 레이아웃 어긋남 | 그대로 두고 다음 릴리즈 ||

### 4-3. 원격 킬스위치 (가장 빠른 수단)
CloudKit Dashboard → `iCloud.com.Ysoup.FeedbackHub` → `RemoteFlags`
→ `flags_com.Ysoup.TokenMemo` 레코드의 해당 필드를 **0** 으로 저장.

| 필드 | 끄면 어떻게 되나 |
|---|---|
| `syncEnabled` | 기기 간 동기화 중단 (로컬 데이터는 그대로) |
| `usageReportingEnabled` | 익명 통계·크래시 진단 전송 중단 |
| `paywallEnabled` | 페이월 노출 중단 |

⚠️ 앱은 **최대 6시간** 주기로 플래그를 받는다(런치 시 갱신). 즉시 전파되지 않는다.
⚠️ 조회 실패 시 기본값은 "켬"이다. 네트워크가 없다고 기능이 꺼지지 않게 한 의도적 선택.

### 4-4. 긴급 심사 요청
App Store Connect → 앱 → **Request Expedited Review**.
남용하면 다음 요청이 거절되므로 **A등급에만** 쓴다. 사유에 "데이터 유실" 같은
구체적 영향을 적어야 통과가 빠르다.

### 4-5. 사고 후 기록
`docs/` 에 `INCIDENT_<날짜>.md` 로 남긴다: 무엇이 / 언제부터 / 몇 명에게 /
어떻게 막았는지 / **왜 테스트가 못 잡았는지**. 마지막 항목이 다음 회귀 테스트가 된다.

## 5. 릴리즈 체크리스트 (복사해서 쓰기)

```

[ ] 릴리즈 노트 작성 (ko/en), docs/release-notes/x.y.z.md (쓰는 규칙은 그 폴더의 README.md)
[ ] 수집 항목이 바뀌었나? → PrivacyInfo.xcprivacy + App Privacy 설문 동시 갱신
[ ] CI 그린
[ ] sh scripts/predeploy.sh 로컬 통과
[ ] 2절 회귀 체크리스트 통과
[ ] TestFlight 3일 (스키마 변경 시 7일)
[ ] Phased Release 켜고 제출
[ ] 출시 후 3일간 크래시·사용 통계 확인
```
