# 점진적 노출과 말 거는 자리

기능을 **잠그지 않고, 지금 필요 없는 것을 안 보여 준다.** 그리고 **한 번에 한 목소리만 낸다.**
이 문서는 그 두 가지를 클립키보드에서 어떻게 지킬지 정한다.

- 판정 모델: `docs/product/USER_STATE_MODEL.md` (`UserState` · `UserSurface`)
- 쓰임새 맞춤: `docs/product/ADAPTIVE_FIT.md` (`PersonaResolver` · `FeatureFit` · `PersonaEdition`)
- 메타포: `docs/design/METAPHOR_PARCEL.md`

---

## 0. 결론: 페르소나별로 설계하지 않는다

페르소나마다 노출 순서를 따로 만들면 표가 넷이 되고, 확신이 없는 사람(대부분의 첫 주)은
어느 표에도 속하지 않는다. 페르소나는 단축어를 **4점 이상** 모아야 확신이 서므로,
첫 세션의 노출을 정할 수가 애초에 없다.

그래서 세 축으로 나눈다. 축마다 답하는 물음이 하나씩이고, 서로의 물음에 답하지 않는다.

| 축 | 묻는 것 | 정하는 것 | 근거 |
| --- | --- | --- | --- |
| **층** | 이 기능이 화면에 있는가 | `UserSurface` 노출 | 행동(숙련도 + 필요해진 순간). **모두에게 같다** |
| **판** | 그 자리를 무엇으로 채우나 | 예시 · 필수 칸 · 마트 · 키보드 붙박이 · 같은 층 안의 차례 | 페르소나. 확신 없으면 모두의 판 |
| **목소리** | 지금 먼저 말을 걸까 | 띠 · 팁 · 시트 하나를 고른다 | 활동 · 예산 · 우선순위. 한 곳(`PromptArbiter`)에서만 |

> 규칙: **페르소나는 층을 옮기지 못하고, 말을 걸지 말지도 정하지 못한다.**
> 노마드라고 콤보가 1층에 오지 않는다. 의존 그래프는 사람을 가리지 않는다.
> 페르소나가 할 수 있는 것은 같은 층 안의 차례와 채울 내용뿐이다.

## 2. 층: 무엇이 화면에 있는가

### 의존 그래프

"이 기능을 쓰려면 무엇을 먼저 알아야 하나" 로 줄을 세운다. 택배 메타포가 그대로 층이다.

```
1층  봉투 하나        단축어 만들기 · 탭해서 복사 · 키보드에서 넣기
2층  봉투가 쌓인다    클립보드에서 만들기 · 즐겨찾기 · 백업
3층  봉투를 고른다    빈칸(운송장) · 검색·순서 · 카테고리 · 꾸미기 · 키보드 판
4층  봉투를 묶는다    콤보(택배상자) · 통계·여권 · 위젯·제어센터 · 맥 앱
```

1층은 이 앱을 깐 이유라 누구에게도 가리지 않는다. 4층에서 멈춘다.

### 여는 조건: 바닥 + 순간

레벨(`UserLevel`)은 "이 사람에게 낼 수 있는가" 의 **바닥**이다. 그 위에 기능마다
**그것이 필요해진 순간**을 얹는다. 둘 다 맞아야 `.lead` 가 된다. 바닥만 맞으면 `.quiet`.

| 기능 | 바닥 | 필요해진 순간 |
| --- | --- | --- |
| 즐겨찾기 | 꺼냄 | 같은 단축어를 다섯 번 넣었다 |
| 백업 | 꺼냄 | 자기 단축어 5개, 또는 민감한 값을 저장했다 |
| 빈칸 | 꺼냄 | 앞부분이 같은 단축어를 둘 이상 만들었다 |
| 검색 | 꺼냄 | 목록이 한 화면을 넘었다 |
| 카테고리 | 익음 | 자기 단축어가 8개를 넘었다 |
| 꾸미기 | 익음 | (순간 없음. 바닥만) |
| 콤보 | 익음 | 두 단축어를 같은 순서로 연달아 넣은 일이 세 번 |

순간은 `UserStateFacts` 에 값을 하나씩 더해 판정한다. 모두 이미 기기에 있는 값이어야 한다.
**머문 날수(`UserTenure`)는 노출에 쓰지 않는다.** 진단(`Cell`)에만 쓴다.

### 탈출구와 상한선

- 설정 ▸ 화면에 **모든 기능 바로 보기**. 켜면 `.hidden` 이 `.quiet` 로 오른다.
- 앱을 연 횟수가 **20** 을 넘으면 같은 길로 `.hidden` 이 `.quiet` 로 오른다.
- 둘 다 `.lead` 로는 올리지 않고, 말 거는 자리는 건드리지 않는다.
- 감춘 기능도 설정에는 늘 있다. `UserSurface` 는 설정 화면에 쓰지 않는다.

## 3. 판: 그 자리를 무엇으로 채우나

같은 층, 같은 자리에 페르소나가 다른 것을 넣는다. 확신이 없으면 모두의 판이다.

| | 모두 (확신 없음) | 일반 | 노마드 | 직장인 | 학생 |
| --- | --- | --- | --- | --- | --- |
| 필수 세 칸 | 계좌 · 주소 · 연락처 | 계좌 · 주소 · 약속 | 정산 · 시차 · 인보이스 | 명함 · 팔로업 · 주간보고 | 학번 · 교수님 메일 · 조 공지 |
| 3층에서 먼저 | 빈칸 | 빈칸 | 빈칸({시차}) | 빈칸 → 카테고리 | 빈칸({학번}) |
| 4층에서 먼저 | 콤보 | 콤보 | 맥 앱 | 맥 앱 → 콤보 | 콤보 |
| 돈 이야기의 차례 | 보안 → 두 대째 → 백업 | 같음 | 두 대째 → 보안 → 백업 | 두 대째 → 백업 → 보안 | **없음** (공유로 대신) |
| 키보드 붙박이 | 계좌 · 주소 | 계좌 · 주소 | 정산 | 명함 | 학번 |

- 필수 세 칸 · 키보드 붙박이 · 돈 이야기의 차례는 이미 있다(`PersonaEdition` · `FeatureFit`).
  **3층·4층에서 먼저**는 이 문서가 새로 더하는 것이다.
- 페르소나 출처는 **`PersonaResolver` 하나**다. `CategoryStore.selectedPersona` 를 직접 읽는 곳
  (`DidYouKnow` · `SuggestionManager` · 사용 보고)은 걷어 낸다. 예전 선택은 추론에 한 표로만 들어간다.
- "먼저" 는 같은 층 안의 차례다. 층의 바닥과 순간은 위 2절 그대로다.

## 4. 목소리: 지금 먼저 말을 걸까

### 4.1 자리를 넷으로 줄인다

| 자리 | 한 번에 | 무엇이 들어오나 |
| --- | :-: | --- |
| **상태 띠** | 1 | 고장 난 것: 키보드가 안 켜져 있다 · 이용 기간이 끝난다 · 기본 카테고리 이름 정하기 |
| **지금 카드** | 1 | 사용자가 방금 한 일에 대한 답: 방금 복사함 · 빠른 메모 보관함 |
| **제안 카드** | 1 | 고른 하나: 아래 우선순위에서 가장 위 |
| **실행 시트** | 실행당 1 | 새 소식 · 그거 아세요 · 리뷰 · 피드백 · 반값 · 무료 사용 영수증 · 정리 · 공유 |

목록 위에는 많아야 **세 줄**이 선다. 팁(TipKit)은 제안 카드와 같은 예산을 쓴다.
제안 카드가 섰으면 그날 팁은 뜨지 않는다.

### 4.2 우선순위 (종류)

```
상태 > 지금 > 막힘 풀기 > 다음 층 소개 > 돈 > 부탁 > 소식
```

| 종류 | 들어가는 것 |
| --- | --- |
| 막힘 풀기 | `Cell.stuck` 인 사람에게: 예시에서 골라 담기 · 필수 세 칸 · 키보드에서 넣어 보기 |
| 다음 층 소개 | 순간이 막 맞은 기능 하나: 카테고리 제안 · 빈칸 소개 · 한 번에 정리 · 꾸미기 |
| 돈 | 프로 넛지 · 결제 순간 · 무료 사용 카드 · 반값 · 키보드 "n개 남음" · 기간 끝 |
| 부탁 | 리뷰 · 피드백 · 친구에게 알리기 · 팁 부탁 |
| 소식 | 새 소식 · 그거 아세요 |

같은 종류 안의 차례는 판(페르소나)이 정한다(돈 이야기의 차례가 그 예).

### 4.3 예산

| 종류 | 예산 |
| --- | --- |
| 돈 | 앱·키보드 합쳐 **하루 1번**. 그날 거절했으면 3일 쉰다 |
| 부탁 | **7일에 1번**. 리뷰·피드백·공유·팁 부탁이 나눠 쓴다 |
| 소식 | 쓴 날 기준 3일에 1번. 새 소식은 버전이 바뀐 첫 실행에 예산 없이 1번 |
| 실행 시트 | 실행당 1. 그날 첫 실행이 앱 설치 직후면 0 |

예산 기록은 `PromptLedger` 하나에 둔다(App Group, 키보드도 읽고 쓴다).

### 4.4 활동이 마지막으로 덮는다

| 활동 | 남는 것 |
| --- | --- |
| 지금 쓰는 중 | 전부 |
| 휴면 (14일) | 상태 · 지금 뿐 |
| 돌아옴 (7일) | 상태 · 지금 · 새 소식. 돈 · 부탁 · 튜토리얼은 끈다 |

이 층은 말하는 쪽이 아니라 **고르는 쪽**이 적용한다. 그래야 새 말을 더해도 휴면을 빠뜨리지 않는다.

## 5. 코드 모양

```swift
// 말하는 쪽: "말할 거리가 있는가" 만 답한다. 때와 예산은 모른다.
protocol PromptSpeaker {
    var id: PromptID { get }
    var slot: PromptSlot { get }      // .statusBand · .momentCard · .suggestionCard · .launchSheet
    var kind: PromptKind { get }      // .status · .moment · .unblock · .nextFloor · .money · .ask · .news
    var surface: UserSurface? { get } // 층에 걸린 말이면 그 자리
    func hasSomethingToSay(_ context: PromptContext) -> Bool
}

// 판정에 쓰는 값 한 덩어리. 순수하게 만들 수 있어야 시험이 25칸 x 5판을 다 돈다.
struct PromptContext {
    var state: UserState
    var facts: UserStateFacts
    var edition: PersonaEdition.Kind
    var isPro: Bool
    var ledger: PromptLedger.Snapshot
    var now: Date
}

// 고르는 쪽: 자리마다 하나. 순수 함수.
enum PromptArbiter {
    static func pick(_ speakers: [PromptSpeaker], in context: PromptContext) -> [PromptSlot: PromptID]
}
```

- 말하는 쪽은 지금의 판단(`BulkImportNudge.shouldOfferInList` 등)을 그대로 옮겨 담는다.
  오래 벼린 타이밍 판단은 버리지 않는다. 대신 **활동·예산·결·층 검사는 말하는 쪽에서 지운다**.
- `topBanners` 는 `PromptArbiter.pick` 의 결과 세 칸만 그린다.
- `ClipKeyboardApp` 의 `asyncAfter` 계단과 `noOtherModalIsUp` 는 실행 시트 한 칸으로 바뀐다.
  목록·탭이 띄우던 시트도 이 칸으로 들어온다.
- 키보드 확장의 "n개 남음" 띠는 `PromptLedger` 의 돈 예산을 읽는다.

### 합치는 것

| 지금 | 하나로 |
| --- | --- |
| 리뷰 시트 · 이벤트 리뷰 3종 · 저장 뒤 리뷰 | `ReviewSpeaker` 하나. 신호(첫 붙여넣기 · 콤보 완료 · 손에 익음)는 사건으로 받는다 |
| 프로 넛지 · 결제 순간 · 무료 사용 카드 · 반값 · 키보드 n개 남음 | `.money` 종류의 말 다섯. 예산 하나를 나눠 쓴다 |
| `selectedPersona` 직접 읽기 3곳 | `PersonaResolver.profile` |

### 날짜를 행동으로

| 지금 | 바꾼 것 |
| --- | --- |
| 배경 제안: 설치 7일 + 3개 | 레벨 익음 (꾸미기 바닥) |
| 손에 익은 사람 리뷰: 설치 3일 초과 | 쓴 날 3일 + 키보드 5번 |
| 그거 아세요: 24시간, 3일 간격 | 쓴 날 기준 3일에 1번 |
| 백업 결제 순간: 30일 + 20개 | 쓴 날 10일 + 20개 |
| 피드백: 실행 10회, 40회마다 | 쓴 날 10일, 그 뒤 30일마다 |

### 지우는 것

즐겨찾기 넛지(그려지지 않는데 횟수만 깎인다) · 활성화 카드 · 빈칸 힌트 · 가끔 제안 ·
`ReviewManager.shouldShowBanner` · 쓰이지 않는 팁 셋(`KeyboardTip` · `StackInfoTip` · `QuickNoteInboxTip`).
살릴 것이 있으면 `PromptSpeaker` 로 다시 들어온다.

## 6. 옮기는 순서

한 단계가 PR 하나다. 단계마다 앱은 지금처럼 동작해야 한다.

| 단계 | 하는 일 | 보이는 변화 |
| :-: | --- | --- |
| 0 | 죽은 말 지우기 · 페르소나 출처 하나로 | 없음 |
| 1 | `PromptLedger` · `PromptArbiter` · 시험 (단계 흉내 10 x 판 5) | 없음 |
| 2 | 목록 띠를 세 칸으로 | 띠가 동시에 셋 넘게 서지 않는다 |
| 3 | 실행 시트 한 칸 (목록·탭 시트 포함) | 실행 때 시트가 겹치지 않는다 |
| 4 | 돈 예산을 키보드와 나눠 쓰기 | 앱과 키보드가 같은 날 둘 다 돈 이야기를 하지 않는다 |
| 5 | 나머지 17자리를 층에 붙이기 · 탈출구 · 상한선 | 첫 주 화면이 가벼워진다 |
| 6 | 날짜 트리거를 행동으로 | 안 쓰는 사람에게 말을 덜 건다 |

**시험의 모양**: 단계 흉내(`UserStageSimulator`) 10단계 x 판 5개 = 50칸마다
"이 사람이 오늘 보는 것" 을 적은 표를 두고, `PromptArbiter.pick` 결과가 그 표와 같은지 본다.
표가 곧 명세다. 표를 바꾸면 이 문서도 같이 바꾼다.

## 7. 새로 말을 더할 때

1. 어느 자리인가. 상태 · 지금 · 제안 · 실행 시트 넷 중 하나다.
2. 어느 종류인가. 종류가 우선순위와 예산을 정한다.
3. 층에 걸린 말이면 `surface` 를 적었는가.
4. `hasSomethingToSay` 안에서 활동 · 예산 · 날짜를 보고 있지 않은가. 보고 있으면 뺀다.
