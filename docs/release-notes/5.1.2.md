## 이번에 고친 것

### 하나. 키보드가 너무 크다는 말

리뷰가 들어왔다. "keyboard size is too big. And the sudden change in size while
switching doesn't look good."

설정에 `버튼 높이` 슬라이더가 이미 있었지만, 요즘 아이폰에서 그 값은 패널 높이를 거의
바꾸지 못했다. 계산해 보니 화면 크기로 정해지는 바닥값에 늘 걸려서, 슬라이더를 끝까지
내려도 같은 높이가 나왔다. 없는 것과 같았다.

키보드 높이를 세 갈래 프리셋으로 바꿨다(`KeyboardHeightPreset`).

- **시스템과 같게**: 기본 키보드와 같은 높이. 전환할 때 화면이 튀지 않는다.
- **표준**: 지금까지의 높이. (`기본` 은 영어에서 General 로 읽혀서 쓰지 않았다)
- **넉넉하게**: 한 줄 더 보이는 높이.

고른 값이 실제로 몇 pt 인지 설정 화면에서 바로 보여 준다. 익스텐션이 쓰는 그 함수로
계산해서 적으므로 설명과 실물이 어긋나지 않는다.

곁들여 두 가지를 더 열었다.

- **조작 키 크기**: 지우기·보내기 같은 조작 키를 24~44pt 사이에서 정한다.
  중국어 피드백("建议可以调整操作按键大小")이 가리키던 것이다.
- **단축어 높이**: 목록과 키보드의 단축어 칸 높이. 이름을 `버튼 높이` 에서 바꿨다.

**처음 쓸 때 한 번 물어본다.** 온보딩에 레이아웃 장을 더해서(`TutorialChapter.layout`),
설정 화면을 못 찾아도 크기를 한 번은 정하고 지나가게 했다. 리뷰를 남긴 사람이 이 설정이
있는 줄 몰랐을 가능성이 컸기 때문이다.

### 둘. 콤보를 단축어 스택으로

`콤보` 는 이름만으로는 무엇인지 알기 어려웠고, 값이 여러 개인 단축어와 개념이 겹쳤다.
**단축어 스택**으로 넓혔다. 스택에도 키가 있고, 스택 안의 칸마다 키와 값이 있다.

```swift
struct StackItem: Codable, Equatable, Identifiable, Hashable {
    var id: UUID
    var key: String     // 칸 이름
    var value: String
    var reference: UUID?
}
```

칸에 이름이 붙으니 값을 고를 때 무엇을 고르는지 안다(`Memo.displayKey(at:)`).
이름을 안 지은 칸은 `1단계` 처럼 자리로 부르고, 그 말은 그릴 때 만들어서 언어를 바꾸면
따라온다.

**저장 형식은 건드리지 않았다.** 코드 이름만 바뀌고 디스크·전파에 쓰는 철자는 그대로다.

| 코드 | 디스크·전파 |
| --- | --- |
| `stackValues` | `comboValues` |
| `stackInterval` | `comboInterval` |
| `isStack` | `isCombo` |
| 스택 파일 | `combos.data` |
| CloudKit 필드 | `combosAsset` |

인코딩할 때 `stackItems` 와 `comboValues` 를 **둘 다** 쓴다. 새 판에서 지은 칸 이름을
헌 판이 못 읽어도 값은 남고, 헌 판으로 내려도 데이터가 깨지지 않는다.

맥에도 같은 모델을 넣었다. 맥이 `stackItems` 를 모르면 합성 인코더가 그 키를 버려서,
**맥에서 한 번 저장할 때마다 아이폰에서 지은 칸 이름이 지워진다.** 맥은 이 값을 고치지
않고 읽어서 보여 주고 그대로 다시 쓴다.

화면에 보이는 `콤보` 55군데를 `스택` 으로 바꿨다. 러시아어는 어미가 붙는 말이라
Combo 를 Стопка 로 그냥 갈아 끼우면 "Разбить стопка" 같은 문장이 나온다.
40개를 비우고 다시 번역해서 "Разбить стопку" 로 잡고, 용어집(`i18n/glossary.json`)에
스택=Стопка 를 박았다.

### 셋. `{}` 가 잘못되고 배열 순서가 뒤틀린다는 말

두 개로 들어온 피드백이었다.

> 종종 {} 부분이 잘못되고, 배열 순서가 자주 뒤틀려지며
> 편집할 때마다 관리 빈칸 섹션이 자주 뒤집혀 있습니다

원인은 하나였다. 빈칸 값을 여러 개 저장할 때 `addPlaceholderValue` 를 값마다 한 번씩
불렀는데, 이 함수는 **넣는 값을 맨 앞으로 올린다**. 그래서 목록 하나를 통째로 저장하면
순서가 매번 뒤집혔다. 키보드는 `values[0]` 을 기본값으로 집으므로, 뒤집힌 목록에서는
엉뚱한 값이 `{}` 자리에 들어갔다. 세 증상이 같은 뿌리였다.

목록을 주어진 순서 그대로 쓰는 `mergePlaceholderValues(_:for:sourceMemoId:sourceMemoTitle:)`
를 더하고 저장 경로를 그쪽으로 돌렸다. `addPlaceholderValue` 는 값 하나를 앞으로 올리는
용도로 남겨 두되, 반복문에서 부르지 말라는 주석을 달았다.

### 넷. 목록에서 제목과 카드 사이 여백이 덜그럭거린다

화면 녹화를 프레임 단위로 재서 잡았다. 제목과 첫 카드 사이 간격이
`10 → 6 → 5 → 6 → 8 → 15` 로 오르내렸다. 위쪽 여백을 측정값으로 계속 고쳐 쓰는데,
측정이 프레임마다 조금씩 달랐던 것이다.

줄어드는 쪽으로만, 그것도 2pt 넘게 차이 날 때만 받아들인다.

```swift
private static let topInsetDeadband: CGFloat = 2
private func considerTopInset(_ v: CGFloat) {
    guard titleBarSettled, !showsInlineNavTitle, !isPageScrolling else { return }
    guard v > 60, v < 160 else { return }
    guard v < pageTopInset - Self.topInsetDeadband else { return }
    pageTopInset = v
}
```

네 군데 `.onChange` 가 모두 이 문을 지난다. 고친 판에서는 5 에서 멈춰 있다.

⚠️ 처음에 재현이 안 됐던 이유: **갈래 기능이 꺼져 있으면** 위쪽 여백이 상수 8 로
돌아가서 측정 경로를 타지 않는다. 다음에 같은 걸 볼 때는 갈래를 먼저 켜고 본다.
